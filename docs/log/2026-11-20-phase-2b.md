# Phase 2b: 3D hub and scroll motion (20 November 2026)

Built from the hand-written Step 4b prompt (the generator had no prompt for 2b after the phase split, pilot gap 40).

## Built

- Tests first, in their own commit (38e7197), output in `2026-11-20-phase-2b-first-run.txt`: `web/scene/hub.test.ts` (5 tests; failed because the module didn't exist) and `e2e/motion.spec.ts` (6 tests; 4 failed, the two fallback tests passed because the stills were already there, and now guard against the 3D breaking them).
- `web/scene/hub.ts`: the procedural hub (DESIGN.md 6): rounded base and four rounded plates in the four finishes, a light ring on the lights module, the signal line on the energy module. About 1,500 triangles, no textures (rule 1).
- `web/scene/scene.ts`: WebGL renderer (pixel ratio capped at 2, 1.5 on phones), scroll-driven camera, key and fill lights, contact shadow. Renders on demand only.
- `web/scene/start.ts`: GSAP ScrollTrigger with `scrub: 1` over the look-inside section: the hub comes apart over the first 12% of the scroll, stays apart through the chapters, reassembles over the last 10%. Each chapter makes its module active (forward, warmer) and, on wide screens, shows a callout with its name and first spec. The section carries `data-explode` and `data-active` so tests can check it.
- `web/main.ts` loads the 3D only when reduced motion is off and WebGL works; if loading fails, the stills stay.
- CSS: the canvas replaces the chapter still in a sticky area (one pinned area); on phones it is a band at the top (34% of the screen) and the chapters scroll below it.
- `npm run perf` (`playwright.perf.config.ts`, `perf/fps.spec.ts`): frame rate while scrolling the 3D section.
- Playwright starts Chrome with software WebGL (SwiftShader), which headless Chrome needs for the 3D tests.

## Measured

- Frame rate (acceptance test 4): 60 frames per second, 95th percentile frame 16.8 ms, three runs, Pixel 5 profile with 4x CPU slowdown and software WebGL. Above the 50 target, so no rule 8 question. Not yet measured on a real phone.
- The 3D chunk is 655 kB minified, 180 kB compressed, loaded after the page is readable; `chunkSizeWarningLimit` raised to 700 kB so the build has no warnings.

## Choices and departures (also in PLAN.md)

- SVG stills kept instead of renders of the model; the hero keeps its still; sticky instead of a GSAP pin; the frame-rate check outside `npm run check`.
- The phase 2a stills test changed: the chapter still is now replaced by the canvas when WebGL is on, so the test accepts the still or the canvas; the reduced-motion and no-WebGL tests check the still itself.
- On phones the band was first 42% of the screen and chapter headings disappeared under it as soon as they became active; reduced to 34% and the phone chapters become active when their text comes into view below the band.
